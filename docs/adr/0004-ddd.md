# ADR 0004: Domain-Driven Design (DDD) for Earth Observation Workflows

- **Status**: Accepted
- **Date**: 2026-08-02
- **Author**: Chief System Architect

## Context
Earth Observation research spans complex concepts: Area of Interest (AOI), Satellite Data Collections, Spectral Indices (NDVI/LST), Scientific Claims, and Verified Evidence.

## Decision
We model the system using Domain-Driven Design principles:
- **Bounded Contexts**: Research Planning, Literature RAG, Earth Engine Processing, Verification, Reporting.
- **Entities & Value Objects**: `ResearchProject`, `Workflow`, `Dataset`, `Evidence`, `Report`.
- **Domain Events**: Status transitions and audit logs.

## Consequences
- **Positive**: Clear ubiquitous language across scientists and software engineers.
- **Negative**: Initial domain modeling requires upfront alignment.

## Alternatives Considered
- Anemic data model with raw SQL dictionaries: Rejected due to risk of unmaintainable spaghetti code.
